Building a Serverless Chat Platform
with Cloudflare D1

A real-world project — pure frontend + serverless database — NFLSHC Chat

Tech Talk · 2026

A Real Story

Students of Class 202401 at Nanjing Foreign Language School Huaian (NFLSHC) wanted their own chat platform:

  • Multiple chat rooms, real-time messaging, quote-reply, pinning
  • User levels, theme switching, a data dashboard
  • A built-in AI assistant (HZYAI) and global search

But here's the catch — nobody wanted to rent a server.

The Core Problem

❌ Traditional way Buy a cloud server + install a database + write backend APIs + monitor it. High cost, high barrier.
✅ Our choice The browser reads & writes a cloud database directly — zero servers, zero ops.

Answer: move the database onto Cloudflare D1, and use Cloudflare Workers as the gateway.

Frontend uses no framework; the gateway runs on Cloudflare's edge; data lives in a serverless D1 database.

Cloudflare D1 as the Database

  • D1 is Cloudflare's serverless SQLite — pay per request, nearly free at small scale
  • Each business type (label) maps to a different table: chatmessage / user / room / role …
  • Each record is a row; its fields are stored as JSON
// A real chat message (a row in D1, label: chatmessage) { "id": "msg_a1b2c3", "roomId": "room_general", "sender": "huangzhiyuan", "content": "Hello everyone!", "timestamp": "2026-08-09T10:00:00Z" }

The Cloudflare Workers Gateway

  • The Worker exposes REST-style endpoints (/api/messages, /api/legacy/issues, …)
  • Naturally CORS-friendly — the browser calls it directly, no self-hosted proxy needed
  • DB credentials stay hidden at the gateway; the frontend only holds an access token
  • A compatibility layer let the old frontend migrate from GitHub Issues to D1 with almost no changes

Authentication & Permissions

  • Users are identified by an access token, stored in the D1 user table
  • Level system driven by activity: level = floor(sqrt(XP / 10)) + 1
  • Four tier colors — green → blue → purple → gold — to reward participation

Rooms · Roles · AI Assistant

💬 RoomsOne D1 record per room; quote, pin, @mention and code highlighting supported.
🎭 RolesCustom personas; prompts stored in D1, with an optional RAG knowledge base.

Data Dashboard

  • 30-day message trend, 24-hour activity heatmap, word cloud, Top-10 speakers
  • All powered by Chart.js, fed directly from D1 aggregate queries
  • The admin backend (admin.html) reads group-chat stats in real time

Deployment: Near-Zero Cost

  • Frontend hosted on Cloudflare Pages (or Workers Assets), global CDN
  • Gateway deployed as a Cloudflare Worker — one wrangler deploy goes live
  • Database D1 is pay-as-you-go, virtually free at small scale
  • Source is open on github.com/user-henry/nflshcchat (MIT)

Lessons Learned

  • CORS / rate limits: calling third-party APIs directly triggered Cloudflare 1010 — solved by moving to the Worker gateway
  • Schema mismatch: some tables lacked the raw_json column, writes were silently dropped → handle per table
  • Missing stats: text messages wrote only the live table, not the legacy layer → fixed by dual-write on send

What's Next

  • Richer multimodal: text-to-image, text-to-video, speech-to-text and text-to-speech via Workers AI (already live in HZYAI)
  • Bigger RAG knowledge base: more class docs so HZYAI knows the community better
  • More roles & automation: scheduled tasks, reminders, smart summaries of each room

Conclusion

With Cloudflare D1 + Workers, even a student project can have:

Zero servers · Zero DB ops · Near-zero cost · Full-featured
